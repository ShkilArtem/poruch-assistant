# Поруч — локальний домашній асистент

Windows, Python 3.12, Ollama, Parakeet/Whisper, Silero VAD і Supertonic/Piper. Інтерфейс українською відкривається на http://127.0.0.1:8765.

## Встановлення після клонування

Потрібні Windows, Python 3.12 та встановлений Ollama. З кореня репозиторію:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe scripts\download_parakeet.py
.\.venv\Scripts\python.exe scripts\download_tts.py
ollama pull hf.co/google/gemma-4-12B-it-qat-q4_0-gguf:Q4_0
.\run.cmd
```

Завантаження потребує інтернету й вільного місця для моделей. Якщо Ollama ще не працює у фоні, спочатку запусти його. Під час завантаження через сервер проєкту задай `$env:OLLAMA_HOST='127.0.0.1:11435'`. Для стандартного фонового Ollama це не потрібно; обидва сервери використовують спільне локальне сховище моделей за стандартних налаштувань.

Моделі, `.venv`, журнали, записи та каталог `data/` із пам’яттю асистента не входять у Git. Після клонування пам’ять починається порожньою. Node.js потрібен лише для браузерних тестів, а не для звичайного запуску.

## Запуск

З кореня проєкту:

```powershell
.\run.cmd
```

Цей запуск працює навіть за заблокованих PowerShell-скриптів. Він піднімає окремий локальний Ollama на `127.0.0.1:11435` із CUDA 12 для RTX 4070, а потім вебсервер. Фоновий Ollama на `11434` не потрібно зупиняти або запускати повторно. Для ручного підключення іншого сервера задай `ASSISTANT_OLLAMA` перед прямим запуском uvicorn; стандартна адреса застосунку — `http://127.0.0.1:11435`.

Типова розмовна модель — **Gemma 4 12B QAT Q4_0**: `hf.co/google/gemma-4-12B-it-qat-q4_0-gguf:Q4_0`. Вона вже завантажена; для нового встановлення: `ollama pull hf.co/google/gemma-4-12B-it-qat-q4_0-gguf:Q4_0`. Також установлені Qwen3.6 35B-A3B IQ3_XXS та попередня Qwen3.5 9B. Запускні профілі: `run.cmd` / `run-12b.cmd` — Gemma, `run-35b.cmd` — Qwen 35B, `run-9b.cmd` — Qwen 9B. Попередній вебсервер треба зупинити через Ctrl+C. Змінна ASSISTANT_MODEL, якщо вже задана, має пріоритет у звичайному run.cmd.

Для голосу потрібні Parakeet у `models/parakeet-v3` і Supertonic у `models/supertonic-3`. Завантаження описані нижче. Старий Piper залишається доступним як окремий голос. Автоматичного переходу на хмарний API немає.

Для точнішого розпізнавання також потрібен **Whisper large-v3-turbo** у `models/whisper-turbo`: він уже завантажений на цьому ноутбуці. На новому встановленні запусти `.\.venv\Scripts\python.exe scripts/download_asr.py` один раз із мережею. Звичайний запуск моделей не завантажує.

## Розпізнавання мовлення й перевірка власного голосу

Типово використовується **Parakeet TDT 0.6B v3 INT8** через sherpa-onnx на CPU (без VRAM). Завантаження: `.\.venv\Scripts\python.exe scripts/download_parakeet.py`. У списку також залишилися Whisper small та large-v3-turbo. Попередній вибір браузер зберігає: щоб випробувати нову модель, вибери **Parakeet v3** вручну. Перше розпізнавання після зміни моделі включає її завантаження; наступні використовують прогрітий рушій.

Parakeet визначає мову сам, підтримує українську, російську та французьку. Для Whisper можна обрати автоматичне визначення або зафіксувати одну з цих мов (корисно на коротких репліках). Whisper: CPU INT8, beam size 5, температура 0, без тематичних підказок.

У записі кнопкою виправлено два дефекти: захист від відлуння більше не відкидає перші 350 мс явного звернення; при відпусканні кнопки незаповнений хвіст аудіобуфера надсилається перед завершенням репліки (раніше могло губитися до 128 мс). VAD завантажується до готовності сервера, щоб його перше завантаження не блокувало приймання мікрофона.

Відкрий **http://127.0.0.1:8765/asr-test** або посилання «Перевірити розпізнавання мого голосу». Зупини основну сесію. Вибери потрібний мікрофон, прочитай фразу, натисни завершення запису; усі завантажені моделі розпізнають однаковий фрагмент. Є набори українських, російських і французьких фраз; текст можна редагувати. Відсоток WER рахує заміни, пропуски та вставки слів, ігноруючи регістр і пунктуацію. Він корисний лише за точного еталона того, що реально було сказано. Завантаження моделей і прогріте розпізнавання показуються окремо; аудіо не архівується. Звіт можна завантажити вручну.

Останній синтетичний тест (`data/asr-benchmark.json`, автоматичне визначення мови): три українські фрази Piper. Parakeet: прогріте розпізнавання 0,188–0,297 с, WER 0%, 22,2%, 0%. Whisper small: 2,45–3,11 с, WER 0%, 22,2%, 37,5%; turbo: 10,09–11,69 с, WER 0% на всіх трьох. Перший прохід Parakeet із завантаженням: 1,61–9,67 с. Навантаження комп’ютера впливає на час. **Це синтетичний голос, не доказ якості на голосі користувача.** Час ASR не включає паузу VAD, генерацію відповіді й озвучування, тому весь голосовий цикл до секунди не гарантований.

Для порівняння на наявних локальних файлах: `.\.venv\Scripts\python.exe scripts/benchmark_asr.py --manifest samples.json`, де JSON — список об’єктів `{"audio":"phrase.wav","reference":"Точний текст"}`. Шляхи аудіо відносні до JSON. Без manifest скрипт використовує лише синтетичні фрази й явно позначає це у звіті.

Почни сесію, за потреби ввімкни камеру й мікрофон. Дозволи на пристрої надаються браузеру. Утримуй кнопку звернення під час репліки; вона перериває озвучування. Текстовий діалог працює без камери й мікрофона.

Можна запитати «Що ти бачиш на камері?», «Опиши кімнату» або «Що в мене в руках?». Перед текстовим повідомленням і завершенням кнопки звернення браузер надсилає поточний кадр. У контексті діалогу явно вказано, що це зоровий вхід асистента з камери; свіжий кадр має пріоритет над попереднім описом. Якщо кадр старіший за 5 секунд або відсутній, явний запит про камеру отримує повідомлення про відсутність свіжого зображення без генерації опису зі старої історії. помилково розпізнані неоднозначні фрази модель має уточнювати, а не мовчки переписувати.

`scripts/check_camera_dialogue.py` перевіряє справжній діалог із синтетичним кадром та вимкненою камерою; результат — `data/camera-dialogue-check.json`.

Типовий голос — **Supertonic 3**, чоловічий тембр M1. Доступні п’ять чоловічих тембрів M1–M5 та 31 мова, зокрема українська, російська, французька й англійська. Режим «Багатомовне читання (авто)» локально визначає мову тексту через langid й передає її синтезатору. Для коротких неоднозначних фрагментів залишається режим `na`; за помилкової вимови обери конкретну мову читання. Це налаштування вимови, воно не перекладає текст. Розмовна модель відповідає мовою користувача або мовою, яку він просить.

Модель працює локально на CPU, без мережі й VRAM. Одноразове завантаження: `.\.venv\Scripts\python.exe scripts/download_tts.py`. Моделі лежать у `models/supertonic-3`; автоматичне завантаження під час розмови вимкнене. Старий голос **Микита (Piper)** доступний у виборі озвучування; він читає лише українською. Вибір рушія, тембру й мови зберігається браузером. Markdown перед читанням очищується, регістр і мовні символи зберігаються.

Пробний замір (`data/tts-benchmark.json`): фрази тривалістю 5,3–6,5 с створюються за 1,03–1,24 с, короткий початковий фрагмент — за 0,67 с. Це час лише синтезу, не всього голосового циклу. Завантаження й прогрів при запуску сервера — близько 10 с. Зразки для прослуховування: `data/voice-samples`. Швидкість генерації не є оцінкою природності голосу.

 Повзунок гучності 0–100% змінює гучність асистента, включно з поточним відтворенням, і запам’ятовується в браузері.

**Швидкість читання** регулюється від 0,5× до 2×. Вона змінює поточний та наступні аудіофрагменти зі збереженням висоти голосу браузером і запам’ятовується в цьому браузері. Це швидкість відтворення, а не прискорення обчислень моделі.

**«Розмова без кнопки»** автоматично вмикає мікрофон під час активної сесії (із дозволом браузера) й надсилає кожну завершену голосову репліку як пряме звернення. Відповідь більше не залежить від хвилинного інтервалу ініціативних реплік. Вибір режиму запам’ятовується; «Вимкнути мікрофон» і «Зупинити» припиняють захоплення. За замовчуванням власне озвучування призупиняє обробку мікрофона.

Додаткова опція **«Слухати під час відповіді (для навушників)»** залишає обробку мовлення активною й під час озвучування: завершена репліка користувача перериває попередню відповідь. Увімкнене браузерне ехопоглинання, а текст, що збігається з нещодавно озвученим, відкидається. Це не гарантує відсутність акустичного відлуння: цей режим розрахований на навушники. Поза активною сесією мікрофон не захоплюється. Перевірки маршрутизації вводу й фільтра повторення автоматизовані; акустичну якість на реальних пристроях потрібно перевірити окремо.

Озвучування працює паралельно з генерацією відповіді: перша фраза передається синтезатору після перших чотирьох завершених слів (або раніше за короткого речення), далі — реченнями до 180 символів. Supertonic завантажується й прогрівається до готовності сервера, використовує чотири потоки CPU. Браузер програє WAV-фрагменти по черзі й, якщо не ввімкнений режим слухання під час відповіді, тримає обробку мікрофона призупиненою також у проміжках між фрагментами. Кнопка звернення, новий текст чи зупинка сесії очищають чергу; запізнілий звук попередньої відповіді відкидається.

Перемикач **«Показувати текст разом із голосом»** увімкнений за замовчуванням. Видимий текст поповнюється фразами при початку їхнього відтворення, щоб готовий текст не випереджав голос. Це синхронізація показу, а не зменшення часу обчислення моделі. Вимкнення цього перемикача повертає негайний показ текстових токенів. За вимкненого голосу або помилки відтворення текст показується одразу.

Остання перевірка Qwen3.5 9B з прогрітим Piper (`data/model-comparison.json`): текстовий запит — перше аудіо 0,50–0,61 с; тестовий кадр — 0,33–0,41 с. Повний текст завершувався за 2,2–3,1 с. Раніше в цій перевірці інший промпт з кадром потребував 1,06 с до аудіо. Заміри рахуються від отриманого текстового запиту до відправлення першого WAV на сервері: вони **не включають ASR, мережеву доставку й запуск браузерного відтворення**. Повторні промпти отримують перевагу кешування; складні сцени, холодне завантаження або навантаження можуть перевищити 1 с. У поточному середовищі Ollama розмістив 87% 9B-моделі на GPU, решту на CPU; гарантованого повного голосового циклу до секунди немає.

Повторити вимірювання: `.\.venv\Scripts\python.exe scripts/benchmark_models.py --models qwen3.5:9b`. Спостереження також отримало заборону вигадувати емоції, наміри та дії поза кадром. Це зменшує підстави для таких відповідей, але не гарантує відсутність помилок моделі.

**Самостійні коментарі стосуються лише суттєвих нових подій за замовчуванням.** Модель порівнює попередній проаналізований кадр із поточним і повертає значущість, стабільний ключ переходу та впевненість. Початковий кадр встановлює сцену без озвучування. Поява/зникнення людини чи помітного предмета або велика зміна оточення можуть викликати репліку за впевненості щонайменше 0,8. Зміни пози, міміки, яскравості й рухи рук за замовчуванням мовчать. Повтор того самого ключа події або тексту блокується. Для іншої суттєвої події немає глобальної хвилинної паузи.

Перемикач «Також коментувати дрібні зміни (частіше)» дозволяє minor-події не частіше ніж раз на 30 секунд; він вимкнений за замовчуванням. «Досить мені описувати камеру» також вимикає дрібні коментарі, залишаючи суттєві події. Загальний перемикач «Коментувати побачене» вимикає самостійні репліки повністю.

Кожен модельний запит прямого діалогу отримує свіжий доступний кадр, навіть якщо формулювання не містить слова «камера». У системній інструкції кадр позначений як допоміжний контекст: пріоритет має зміст останньої репліки, а опис кімнати без потреби заборонений. Видиме можна використовувати для неявних запитів про оточення; гіпотези потрібно відділяти від спостережень. Наявний кадр явно означає доступ до зображення, тому модель не повинна називати працюючу камеру вимкненою. Попередні пари запит/відповідь з явним описом камери прибираються з контексту неявних/невізуальних ходів, щоб зменшувати повторення. Спостереження працює окремо й не додає свої репліки до історії прямого діалогу.

Перевірка камери виконується кожні 3 секунди, коли модель і відтворення вільні; за відсутності помітної піксельної зміни аналіз може відкладатися до 10 секунд. Пряме звернення має пріоритет. Розпізнавання значущості є оцінкою моделі, а не гарантією; швидкі події між кадрами та зміни під час зайнятості можуть бути пропущені. `scripts/check_camera_policy.py` перевіряє реальну модель на синтетичному переході й запитаннях зі скриншота; результат — `data/camera-policy-check.json`.

## Швидкодія

Під час діагностики 16.10.2026 стандартний сервер `11434` тримав модель на **100% CPU**. Окремий сервер із CUDA 12 завантажив її повністю на RTX 4070. У короткому синтетичному текстовому тесті: CPU близько 17 токенів/с, прогрітий GPU близько 80 токенів/с. Це швидкість генерації тексту, а не всього голосового циклу. Холодне завантаження GPU зайняло близько 4,3 с; перший токен в ідентичному повторному запиті — 0,016 с (з кешуванням промпту).

Поточне розміщення GPU/CPU видно у верхньому рядку сторінки після завантаження моделі. Звіти профілювання зберігаються в `data/performance*.json`.

```powershell
.\.venv\Scripts\python.exe scripts/profile_runtime.py
```

Збільшення RAM чи контексту не прискорює автоматично генерацію. Для цього ноутбука головне — повне розміщення моделі у VRAM; Whisper і Piper залишаються на CPU. Контекст 4096 і одна генерація одночасно зменшують конкуренцію за відеопам’ять. Відеоаналіз і перший запуск моделей додають затримку. Кнопка звернення явно запускає відповідь; фонові репліки можуть навмисно ігноруватися.

## Пам’ять

- Форма «Знайомство» зберігає ім’я, звертання, опис кімнати та інтереси як профіль.
- Редактор розрізняє профіль, сталі факти й поточні справи. Неактуальні записи залишаються видимими в редакторі, але не потрапляють у контекст моделі.
- `Запам’ятай інтереси: робототехніка` явно зберігає або оновлює факт за темою. Ця команда працює навіть за вимкненого автоматичного запам’ятовування.
- `Забудь інтереси` видаляє факт. Якщо збігів кілька, потрібно уточнити тему або використати редактор.
- `Що ти про мене знаєш?` показує актуальні збережені факти без звернення до моделі.
- Автоматичне запам’ятовування використовує лише прямі звернення; для факту потрібна точна цитата з повідомлення. Це перевірка джерела, а не гарантія правильного тлумачення моделлю.
- Кожні чотири завершені прямі репліки створюється або оновлюється один підсумок поточної сесії. Незавершений блок при зупинці не зберігається. Зберігаються щонайбільше 50 підсумків, кожен до 1800 символів.
- Повнотекстовий пошук SQLite FTS5 підбирає релевантні факти й підсумки. Профіль має пріоритет; контекст пам’яті обмежений 3000 символами.
- Видалення факту очищає **всі** підсумки, бо вони можуть містити його перефразування. Зміна тексту чи актуальності факту також очищає підсумки. Активна відповідь скасовується, а контекст діалогу очищається. Підсумки можна видаляти окремо.

База: `data/memory.sqlite3`. Старий формат фактів мігрує при запуску. Записи містять джерело, дату, впевненість і актуальність. Значення впевненості є позначкою походження, а не каліброваною статистичною оцінкою. Сцена з камери зберігається лише в RAM; сирі діалоги, аудіо й відео сесій не архівуються. Бенчмарк окремо створює синтетичний зразок голосу `data/voice-sample.wav`.

## Перевірки та стан плану

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp data/pytest-check
.\.venv\Scripts\python.exe scripts/benchmark.py
```

Тести використовують тимчасові бази й підставні моделі; бенчмарк перевіряє справжні локальні моделі. Повторна перевірка з GPU і голосом Микити (`data/benchmark.json`): розпізнавання синтетичної фрази 2,88 с, текстова відповідь 1,45 с, аналіз тестового зображення 0,97 с, синтез фрази 2,22 с. Це окремі вимірювання, частково з початковим завантаженням; вони не підтверджують ціль початку повної голосової відповіді за 5 секунд. Початковий імпорт/завантаження VAD зайняв 9,59 с і впливає на перше використання мікрофона. Параметри моделі використовують контекст 4096; перехід до запланованих 8192 потребує вимірювання VRAM і затримки.

Наступні перевірки: повна 30-хвилинна сесія на реальних пристроях, від’єднання камери/мікрофона, відновлення після недоступності Ollama, перевірка без мережі та вимірювання RAM/VRAM. Вони ще не пройдені. Хмарний режим і Sign in with ChatGPT не реалізовані.


## Експеримент із більшою моделлю

`run-35b.cmd` запускає асистента з локальною `hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ3_XXS` (Unsloth, 35B загалом / 3B активних). `run-9b.cmd` явно повертає Qwen3.5 9B. Перед зміною зупини попередній вебсервер через Ctrl+C. Скрипти змінюють змінну лише для запущеного процесу; вони не змінюють системні налаштування. Звичайний `run.cmd` використовує Gemma 12B QAT із config.py або наявну змінну ASSISTANT_MODEL.

Одноразове завантаження: `ollama pull hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ3_XXS` (потрібен запущений Ollama; для сервера проєкту задай OLLAMA_HOST=127.0.0.1:11435). Модель і проєктор зберігаються у сховищі Ollama на диску C. Потрібно близько 14,2 ГБ дискового простору. Перша відповідь після зміни моделі включає її завантаження.

Порівняння через реальний код діалогу: `.\.venv\Scripts\python.exe scripts/trial_large_model.py --models qwen3.5:9b hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ3_XXS --audio`. Тест використовує окрему пам’ять у RAM і синтетичне зображення, не відкриває базу користувача. Перевіряє перемикання мови, наступну французьку репліку, інструкцію відповісти числом, використання профілю та опис фігур. Час до тексту й аудіо вимірюється окремо. Прості автоматичні перевірки не доводять загальну перевагу моделі.


Профілі генерації: Gemma 4 — temperature=1.0, top_p=0.95, top_k=64; Qwen3.6 — temperature=0.7, top_p=0.8, top_k=20. Для структурованих відповідей залишено temperature=0.2. Thinking вимкнений, контекст 4096. Налаштування не додають параметрів і самі по собі не гарантують кращого діалогу.


Результати фактичного порівняння: `data/model-trial-report.md`. Gemma 12B QAT обрана типовою; 35B доступна для експериментів. У фінальному тесті перше аудіо: Gemma 1,13–1,73 с без кадру / 2,97 с із кадром, Qwen35 1,89–5,00 с / 6,61 с. ASR і браузер не входять у ці вимірювання. Жодна нова модель не підтвердила стабільну повну голосову відповідь до секунди.
